## 1. 使命

把「一线牵」从飞书机器人 + 飞书 H5 改造成独立网页产品：

- 用户不需要飞书账号，也不在飞书聊天；手机号 + 密码登录。
- 既有用户可从 testapp 迁移，先用一次性链接设密码，之后正常登录。
- 用户端必须完整、可用、与原版基本无感。
- 管理台必须可用：审核、活动、匹配、积分、举报、角色权限、审计。
- 数据库与媒体不依赖飞书；飞书只存在于 v1 旧系统。

## 2. 最高原则与非目标

1. **成品导向，不做 POC**；每个功能都要能给真实用户使用。
2. **用户功能不可省**；本文件 Must-Have 全部通过前，不宣布完工。
3. **单一真相源**；PostgreSQL 是权威，R2 只存媒体/备份，Bitable 不是 runtime。
4. **用户端复用 v1，管理台 SSR**；不重写用户端，不引入第二套管理 UI。
5. **安全与隐私默认开启**；密码、session、CSRF、RBAC、审计、私有媒体、最小权限。
6. **先 staging 后生产**；不在生产做实验；生产切换必须另行走查、备份与回滚演练。
7. **没有证据就不算完成**；每个判准要有命令、输出、测试或验收记录。
8. **文字统一简体中文**；代码注释、界面、提交说明与变更摘要一律简体中文。

**首版明确不做**：飞书机器人/表单/名片/Bitable runtime；短信 OTP；即时聊天/IM；像素级 UI 复刻；微服务/Kubernetes；用户端重新设计；为旧浏览器维护第二套完整用户 UI。
（E2 相互喜欢交换微信号、D10 每周推荐位曾于 2026-10-24 暂缓，后由 `docs/DECISIONS.md` §3.1/§3.2 重新纳入；旧决策 26/27 见该文件 §5 索引。以本文件清单为准。）

## 3. 架构硬约束

- 后端 Go 1.24（以 `go.mod` 为准）；单 binary 模块化单体；PostgreSQL 16；R2 私有桶。
- 公开入口固定 server2（香港）TLS relay，回源 server1；DNS 不直指 server1，不开 Cloudflare 橙云。
- 用户端复用 v1 Vue 3 + Vant SPA；Go 提供 `/legacy/api/*`、session 与媒体代理。
- 管理台 Go `html/template` SSR，只经用户 SPA 同源 iframe；浏览器顶层 `/admin` 一律 303 到 `/?admin=1`；受权媒体串流为例外。
- 不新增 Redis 或消息队列；当前正确性不依赖缓存或队列。
- 媒体只经应用 `/media/{id}` 串流；R2 URL 不进浏览器。
- 登录、注册、启用、改密页由服务端渲染；扫描防护后文案由 JS 注入，禁用 JS 时不可用（已知取舍）。用户 SPA 与管理台需要 JavaScript。
- 支持范围：iOS 14.5+/Safari 14.1+、Chrome/WebView 84+、Firefox 74+；低于范围不承诺完整 UI。

## 4. 验收清单（Must-Have）

### A. 登录与账号

- [ ] A1. 手机号＋密码登录；错误信息不区分账号/密码；失败锁定与 rate limit。
- [ ] A2. 一次性 activation token：24h、一次性、设定密码后自动登录；重用/过期有明确页面。
- [ ] A3. 小天使/管理员可为用户生成临时密码；首登强制修改（P1）。
- [ ] A4. 忘记密码：管理员重置（不依赖短信）。
- [ ] A5. 退出登录：撤销 DB session、清 cookie。
- [ ] A6. 既有 testapp 用户可用 activation link 设定密码；U-0006 使用真实资料。
- [ ] A7. 账号状态门禁：待审核/审核不通过/已退出只可看提示；disabled 不可登录。
- [ ] A8. 观察员角色可登录、只读；一般/观察员可切换（依原规则）。
